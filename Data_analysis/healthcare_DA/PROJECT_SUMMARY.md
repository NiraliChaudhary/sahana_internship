## 🏗️ ARCHITECTURE OVERVIEW

### Class Structure (OOP Design)

```
DataLoader (Input)
    ↓
DataCleaner (Cleaning & Validation)
    ↓
DataAnalyzer (Analysis & Insights)
    ↓
├─→ VisualizationEngine (Charts)
├─→ InsightGenerator (Reports)
└─→ HealthcareAnalyticsPipeline (Orchestration)
    ↓
Output (Visualizations, Reports, Insights)
```

### Design Patterns Used

1. **Single Responsibility Principle**
   - Each class has one clear purpose
   - Separation of concerns
   - Easy to test and maintain

2. **Fluent Interface**
   - Method chaining for cleaner code
   - Example: `cleaner.clean_names().remove_duplicates().validate_data_types()`

3. **Dataclass Pattern**
   - Type-safe data containers
   - Structured metrics storage

4. **Factory Pattern**
   - Pipeline orchestrates workflow
   - Clean separation of phases
